Tiny optimization target for the `optimize-loop` vhs demo (`demo/tapes/optimize-loop.tape`). `slow_fib.py` computes `fib(n)` by plain double recursion with no memoization, so `work()` (which returns `fib(30)` = 832040) takes roughly 300–400 ms, while the same call memoized with `functools.lru_cache` finishes in under 5 ms; `test_slow_fib.py` is the guard (`python3 -m unittest -q test_slow_fib` must exit 0) and `metric.sh` prints one integer — milliseconds for `work()`, lower is better. The demo runs two hypotheses: lru_cache (KEEP) and then removing the cache while switching to `fib(32)`, which intentionally regresses both the metric and the story ("batch amortization"), so the optimize skill's DISCARD path and its real `git reset --hard HEAD~1` revert are exercised on camera.
